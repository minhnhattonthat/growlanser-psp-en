references/platform-psp.md: in a relocatable PRX the HI16/LO16 immediates are relative to the segment they address (here data vaddr 0x11D3C0), not to 0: a lui/addiu scan must add the target segment's vaddr (growlanser-psp-en tools/elfrefs.py).

references/platform-psp.md: PPSSPP WebSocket `gpu.record.dump` replies only after the next frame renders: send it, run the CPU (cpu.runUntilTime), then read the reply (tools/gedump.py). v6 dumps are zstd: 0x20-byte header, 9-byte commands (type, sz, ptr into pushbuf); TEXTURE0 data = the raw swizzled texture bytes, so ram.find() gives the texture's RAM address. Fastest way to find a screen's source file.

references/emulator-qa.md: PPSSPP WebSocket `cpu.resume` sends no ticketed reply, so psp.WS.call('cpu.resume') hangs to the socket timeout; send it raw (ws._send). psp.Run.run_to also hangs if a breakpoint stops the CPU before the target (it waits for a second cpu.stepping): for breakpoint work call cpu.runUntilTime yourself and check the stepping event's pc (growlanser-psp-en tools/debug/warp.py vm_jump).
references/emulator-qa.md: PPSSPPHeadless exec and memory (write) breakpoints work over the WebSocket (`cpu.breakpoint.add`, `memory.breakpoint.add {address,size,write:true}`); the hit arrives as cpu.stepping with reason memory.breakpoint and `cpu.getAllRegs` gives the writer's registers: quickest way from a display copy to the real variable.
references/emulator-qa.md: psp.py `--sav DIR` copies a single save folder under DIR's own basename: keep the game's folder name (e.g. work/saves/x/ULJM05423GR_DATA and pass work/saves/x), or the game finds no save.
references/emulator-qa.md: PSP save editor: sceSavedata DATA files are encrypted, so a lazy save.py pokes RAM and saves through the in-game menu (the game writes its own checksum); check = load + read RAM back (growlanser-psp-en tools/debug/save.py).
